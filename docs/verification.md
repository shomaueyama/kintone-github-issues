# 動作確認の記録

kintone 開発者環境での手動確認。確認した日付と結果を残す。未確認の項目は空欄のまま。

環境: kintone 開発者ライセンス(1年・無料)。確認用アプリ「問い合わせ管理(GitHub 連携)」。
GitHub 側: 確認用の private リポジトリと Fine-grained PAT(Issues: Read and write)。

| # | 確認項目 | 期待する動作 | 結果 | 日付 |
|---|---|---|---|---|
| 1 | プラグインの読み込み | システム管理でエラーなく読み込め、アプリに追加できる | | |
| 2 | 設定画面の表示 | アプリのフィールドが種類ごとに絞られてドロップダウンに出る | | |
| 3 | 設定の保存(トークンあり) | 保存後にアプリ設定画面へ戻る。再度開くとトークン欄は「保存済み」表示 | | |
| 4 | 設定の保存(トークンなし・保存済み) | トークンを再入力しなくても保存できる | | |
| 5 | リポジトリ変更時 | トークン未入力だとエラーで止まる | | |
| 6 | 作成(正常) | Issue が GitHub にでき、番号・URL・状態・同期日時がレコードに入る。画面が再読み込みされてリンクと open バッジが出る | | |
| 7 | 作成(タイトル空) | GitHub を呼ばずにエラー表示 | | |
| 8 | 作成(トークン無効) | 401 の案内が出る | | |
| 9 | 作成(リポジトリ名誤り) | 404 の案内が出る | | |
| 10 | 二重作成防止 | 2つのタブで同じレコードを開き、片方で作成した後にもう片方で押すと、作成せずに再読み込みされる | | |
| 11 | 同期(変更あり) | GitHub で Issue を閉じ、「同期」を押すと状態が closed になる | | |
| 12 | 同期(変更なし) | 「最新です」の表示だけでレコードは更新されない(更新履歴に残らない) | | |
| 13 | 部分失敗の復旧 | 番号フィールドを書き込み不可にして作成すると、URL と再試行ボタンが出る。権限を戻して再試行すると書き込める | | |
| 14 | 設定未完了 | 必須項目が未設定のアプリでは詳細画面に何も出ない | | |

## 確認できていない仕様上の前提

- `kintone.plugin.app.setProxyConfig` を同じ URL で GET と POST の2回呼んだとき、両方が保持されること(#3 と #6 / #11 で確認する)
- `kintone.plugin.app.proxy` の GET で `data` に空文字を渡して問題ないこと(#11 で確認する)
