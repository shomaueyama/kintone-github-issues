# ADR 0001: 自動作成ではなく明示的なボタンにする

- 状態: 採用
- 日付: 2026-10-29

## 背景

レコードから GitHub Issue を作るタイミングには、次の2通りがある。

1. レコードを保存したら自動で作る(`app.record.create.submit.success` などのイベント)
2. 詳細画面のボタンを押したときだけ作る

問い合わせ管理のアプリでは、レコードの大半は Issue にする必要がない(重複、問い合わせのみ、営業対応など)。また、保存時の自動作成はレコードの保存と GitHub への書き込みが同時に起きるため、片方だけ成功したときの扱いが難しい。

## 決定

詳細画面に「GitHub Issue を作成」ボタンを出し、押したときだけ作る。保存時の自動作成はしない。

## 検討した他の案

**保存時に自動作成。** 手間はいちばん少ないが、不要な Issue が増える。ユーザーが「作るべきか」を判断する機会がない。保存イベントの中で外部 API を呼ぶと、GitHub が遅いときにレコード保存が遅くなる。

**チェックボックス「Issue を作る」を立てて保存したら作成。** 判断の機会はあるが、保存イベントの問題は残る。設定項目も1つ増える。

## 結果

- 作成は常にユーザーの操作に紐づくので、「誰がいつ作ったか」が kintone の更新履歴と一致する
- 外部 API の失敗はボタンの操作に対する失敗として表示でき、レコード保存を巻き込まない
- 作成し忘れは起こりうる。一覧画面に「Issue 未作成」の絞り込みを用意する運用で補う(プラグインの機能にはしない)
